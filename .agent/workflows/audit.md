当用户输入 `/audit` 或要求“审计系统”、“检查 Agent Bug”时，请严格按照以下步骤对 Agent 的指定范围进行深度体检，并产出结构化的体检报告。

## 审计准备阶段
1. **确认审计范围**：
   - 询问用户：“您希望进行【全局代码/架构库审计】，还是针对【特定的 Prompt 模块 / Workflow 工作流】进行局部深度排查？”
   - 获取用户指示后，开始读取目标范围内的底层文件（如 `SKILL.md`, `instructions.md`, `Prompts/` 下的核心文件等）。

## 深度测评执行阶段 (四维审计基准)
请扮演一名资深的 AI 架构师，从以下四个维度扫描文件上下文：

1. **🐞 逻辑冲突与 Bug (Logic & Reliability)**
   - 检查文件间的逻辑是否存在自相矛盾？（例如：全局红线文件约束了某条件，但局部 prompt 又鼓励反向操作）。
   - 检查文件路径、变量调用关系、上下游传递（例如：某个参数要求读取 JSON 文件，但未指定解析方法）是否会出现报错的死胡同。

2. **⚡ 高效性与 Token 损耗 (Efficiency & Token Economy)**
   - 审查 Prompt 是否有冗余、废话连篇的约束？
   - 业务流转过程（如多工具同时串联）是否过于笨重？能否通过合并指令来降低 Token 输出/输入代价？
   - 识别出可以“缓存”或“压缩”的记忆节点。

3. **🛡️ 护栏与安全性 (Security & Constraint Enforcement)**
   - 对现有的数据脱敏警示或合规红线（如五维商业红线）进行压力测试评估：它是否足够坚固，或者是否容易被用户的话术绕开？

4. **🎯 实用性与体验 (Usability & User Flow)**
   - 评估这套流程对新用户的“交互摩擦力”是否太高？能否更自动化或减少用户的文字输入量？
   - 报错与边缘场景处理：如果用户输入了一段毫无意义或极其无理的要求，这部分逻辑能否优雅兜底？

## 报告生成与自动化存档阶段
完成扫描后，请自动起草一份专业的《Agent 审计与优化报告》，并严格按照以下生命周期执行：

1. **确定活动版本目录**：
   - 读取 `_docs/_history/` 下最新的版本号（如 `v5.0.0`）。
   - 如果不存在任何版本目录，默认提示用户运行 `/init-version`。

2. **静默文件持久化 (Silently Archiving)**：
   - 必须调用 `write_to_file` 工具，将完整的审计内容保存至 `_docs/_history/[当前版本]/audit_report.md`。
   - 文件内容必须包含审计日期、环境 Context 以及 P0/P1/P2 的详细分级描述。

3. **对话框结构化交付 (User-Facing Report)**：
   - 向用户展示以下精炼后的报告摘要：
   
   ### 📋 审计体检报告 (Audit Report Snapshot)
   - **【P0/严重错误】**：会导致 Agent 宕机、死循环、读写文件失败、或者红线被穿透的重大漏洞。
   - **【P1/执行瑕疵】**：工作流不通畅、Prompt 互相打架或可能引发幻觉的风险点。
   - **【P2/体验优化建言】**：关于减少 Token 消耗、提升打字速度、改进用户逻辑的架构建议。
   - **【实操落地步骤】**：针对上述漏洞提出 1-3 个解决动作，并询问：“全量审计报告已存至 `_history` 目录。需要我一键帮您修复 P0/P1 问题吗？”
